# Form Component Requirements

## Overview

This document defines the principles and requirements for creating form components in the Christian Poetry Platform, ensuring consistency, type safety, performance, and compliance with Feature-Sliced Design (FSD) architecture, `tech_prd.md`, and `form_pattern.md`. All form components generated by CursorAI must adhere to these guidelines.

## Design Principles

### UX/UI Principles
- **Progressive Disclosure**: Break complex forms into logical sections, using conditional rendering for optional fields (e.g., `CategoryCreateForm.tsx`).
- **Instant Feedback**: Provide real-time validation feedback using `react-hook-form` and Zod.
- **Accessibility**: Include ARIA attributes (`aria-labelledby`, `aria-describedby`, `aria-invalid`), keyboard navigation, and semantic markup.
- **Responsiveness**: Ensure forms display correctly on all devices using Tailwind CSS responsive classes.
- **Consistency**: Use consistent styling (via `shadcn/ui` and Tailwind CSS) and locale constants (e.g., `LocaleMessages.ts`).

### Technical Principles
- **Composition**: Build forms from reusable `shadcn/ui` components (e.g., `Form`, `FormField`, `Input`, `Button`).
- **Reusability**: Extract common logic into hooks (`lib/hooks`) and utilities (`lib/utils`).
- **Type Safety**: Use TypeScript and Zod for strict typing of form data and server responses.
- **Validation**: Implement client-side validation with Zod and server-side validation in server actions.
- **Server Actions**: Use Next.js Server Actions for all form submissions, with proper cache revalidation.
- **Performance**: Use `startTransition` for non-blocking UI updates during submission.

## Form Component Structure

### Component Structure
```typescript
// src/features/{feature-name}/ui/{FormComponent}.tsx
'use client';

import { useActionState, startTransition } from 'react';
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { Form, FormControl, FormField, FormItem, FormLabel, FormMessage } from '@/shared/ui/shadcnComponents/form';
import { Input } from '@/shared/ui/shadcnComponents/input';
import { Button } from '@/shared/ui/shadcnComponents/button';
import { LocaleMessages } from '@/shared/constants/LocaleMessages';
import { use{FormName}Form } from '../lib/hooks/use{FormName}Form';
import { submit{FormName} } from '../server-actions/submit{FormName}';
import { formSchema, type FormData } from '../model/schemas';

interface {FormName}FormProps {
  defaultValues?: Partial<FormData>;
  onSuccess?: (data: FormData) => void;
  onCancel?: () => void;
}

export const {FormName}Form = ({ defaultValues, onSuccess, onCancel }: {FormName}FormProps) => {
  const [state, formAction] = useActionState(submit{FormName}, { success: false, message: '' });
  const form = useForm<FormData>({
    resolver: zodResolver(formSchema),
    defaultValues,
  });
  const { handleSubmit } = use{FormName}Form({ onSuccess });

  const onSubmit = (data: FormData) => {
    const formData = handleSubmit(data);
    startTransition(() => {
      formAction(formData);
    });
  };

  return (
    <Form {...form}>
      <form onSubmit={form.handleSubmit(onSubmit)} className="space-y-6">
        <FormField
          control={form.control}
          name="fieldName"
          render={({ field }) => (
            <FormItem>
              <FormLabel id="fieldName-label">{LocaleMessages.RU.FIELD_NAME}</FormLabel>
              <FormControl>
                <Input
                  {...field}
                  placeholder={LocaleMessages.RU.FIELD_NAME_PLACEHOLDER}
                  aria-labelledby="fieldName-label"
                  aria-describedby="fieldName-error"
                  aria-invalid={!!form.formState.errors.fieldName}
                  className="bg-background border-input text-foreground"
                />
              </FormControl>
              <FormMessage id="fieldName-error" />
            </FormItem>
          )}
        />
        {state.message && (
          <div
            className={`text-sm p-3 rounded-md border ${
              state.success ? 'bg-green-50 text-green-700 border-green-200' : 'bg-red-50 text-red-700 border-red-200'
            }`}
            role="alert"
            aria-live="polite"
          >
            {state.message}
          </div>
        )}
        <div className="flex items-center justify-end space-x-2">
          {onCancel && (
            <Button
              type="button"
              variant="outline"
              onClick={() => {
                form.reset();
                onCancel();
              }}
              className="bg-background border-input text-foreground"
            >
              {LocaleMessages.RU.CANCEL}
            </Button>
          )}
          <SubmitButton />
        </div>
      </form>
    </Form>
  );
};

const SubmitButton = () => {
  const { pending } = useFormStatus();
  return (
    <Button
      type="submit"
      disabled={pending}
      className="bg-primary text-primary-foreground hover:bg-primary/90 disabled:opacity-50"
    >
      {pending ? LocaleMessages.RU.SUBMITTING : LocaleMessages.RU.SUBMIT}
    </Button>
  );
};
```

### Schema Definition
```typescript
// src/features/{feature-name}/model/schemas.ts
import { z } from 'zod';
import { LocaleMessages } from '@/shared/constants/LocaleMessages';

export const formSchema = z.object({
  fieldName: z.string().min(1, LocaleMessages.RU.REQUIRED_FIELD),
  // Add other fields with validation
});

export type FormData = z.infer<typeof formSchema>;
```

### Custom Hook
```typescript
// src/features/{feature-name}/lib/hooks/use{FormName}Form.ts
import { useCallback } from 'react';
import { prepareFormData } from '../utils/formUtils';
import type { FormData } from '../../model/schemas';

interface Use{FormName}FormProps {
  onSuccess?: (data: FormData) => void;
}

export const use{FormName}Form = ({ onSuccess }: Use{FormName}FormProps) => {
  const handleSubmit = useCallback((data: FormData) => {
    const formData = prepareFormData(data);
    if (onSuccess) {
      onSuccess(data);
    }
    return formData;
  }, [onSuccess]);

  return { handleSubmit };
};
```

### Form Utilities
```typescript
// src/features/{feature-name}/lib/utils/formUtils.ts
export const prepareFormData = (data: Record<string, any>): FormData => {
  const formData = new FormData();
  Object.entries(data).forEach(([key, value]) => {
    if (value !== undefined && value !== null) {
      formData.append(key, String(value));
    }
  });
  return formData;
};
```

### Server Action
```typescript
// src/features/{feature-name}/server-actions/submit{FormName}.ts
'use server';

import { revalidatePath } from 'next/cache';
import { auth } from '@/shared/api/auth/auth';
import { formSchema } from '../model/schemas';
import { repository } from '@/entities/{entity-name}';

export async function submit{FormName}(formData: FormData) {
  try {
    const session = await auth();
    if (!session?.user) {
      throw new Error('Unauthorized');
    }

    const rawData = {
      fieldName: formData.get('fieldName') as string,
      // Add other fields
    };

    const validatedData = formSchema.parse(rawData);
    const result = await repository.create(validatedData);

    revalidatePath('/relevant/path');

    return {
      success: true,
      message: 'Form submitted successfully',
      data: result,
    };
  } catch (error) {
    console.error('Error submitting form:', error);
    return {
      success: false,
      message: error instanceof Error ? error.message : 'Unknown error',
    };
  }
}
```

## Requirements

### General Requirements
- **Server Actions**: All form submissions must use Next.js Server Actions, located in `server-actions/`.
- **Validation**: Use Zod for client-side and server-side validation, with schemas defined in `model/schemas.ts`.
- **Type Safety**: All form data and server responses must be fully typed using TypeScript.
- **FSD Compliance**: Follow FSD structure (`ui`, `model`, `lib`, `server-actions`) with public APIs exported via `index.ts`.
- **Multilingual Support**: Use `LocaleMessages.ts` for labels, placeholders, and error messages.
- **Error Handling**: Display success/error messages with consistent styling (green for success, red for errors).
- **Performance**: Use `startTransition` for all form submissions to ensure non-blocking UI updates.
- **Accessibility**: Include ARIA attributes and support keyboard navigation.
- **Reusability**: Abstract common logic into hooks (`use{FormName}Form`) and utilities (`formUtils.ts`).

### Code Standards
- Use arrow functions for utilities (e.g., `prepareFormData`).
- Follow naming conventions: PascalCase for components/types, camelCase for functions, kebab-case for CSS modules.
- Write all code comments and documentation in English, per `main_prd.md`.
- Avoid inline styles; use Tailwind CSS classes with semantic tokens.

### Validation Requirements
- **Client-Side**: Use `react-hook-form` with `zodResolver` for real-time validation.
- **Server-Side**: Validate `FormData` in server actions using Zod schemas.
- **Error Messages**: Use locale-specific error messages from `LocaleMessages.ts`.

### Performance Requirements
- Use `startTransition` for all form submissions.
- Memoize components with `React.memo` if they are reused frequently.
- Lazy load heavy components (e.g., rich text editors) when applicable.

### Security Requirements
- Validate all input data on both client and server.
- Sanitize rich text inputs (e.g., using `sanitize-html` for Quill content).
- Ensure server actions check authentication and authorization using `auth()`.

### Testing Requirements
- Write unit tests for Zod schemas (`model/schemas.ts`).
- Write integration tests for server actions (`server-actions/`).
- Write E2E tests for form submission scenarios.

## Best Practices

- **Consistency**: Use the same structure and naming conventions across all forms.
- **Modularity**: Keep components small and focused, delegating logic to hooks and utilities.
- **Documentation**: Update `docs/specs/forms_specs/` with form-specific documentation (e.g., `{formName}_form_structure.md`).
- **Code Review**: Ensure CursorAI validates generated code for FSD compliance, type safety, and adherence to this specification.
